# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"ISIK" (repo: KutunYukselisi) is an Unreal Engine 5.8 game (`EngineAssociation: 5.8` in `ISIK.uproject`). It is a **Blueprint-only project in practice**: `Source/ISIK` is empty, there is no C++ game module, and no build/lint/test commands exist. All gameplay logic lives in `.uasset`/`.umap` binaries under `Content/`, which cannot be meaningfully read or diffed as text — edit them through the Unreal Editor (or the Unreal MCP server, see below), not with file tools.

## Working with the project

- Open `ISIK.uproject` in the Unreal Editor (5.8). Editor startup map: `/Game/Kutun/Maps/L_Tutorial_New`. Packaged-game default map: `/Game/Kutun/Maps/L_Main3DMenu`. Run **one** editor instance: two editors on the same project lock each other's files and saves fail with "MoveFile was unable to move".
- `.mcp.json` registers an `unreal-mcp` HTTP server at `http://127.0.0.1:8000/mcp`. It is served by the editor's `ModelContextProtocol` / `ToolsetRegistry` / `AllToolsets` plugins, so the **editor must be running** for it to connect (otherwise `ECONNREFUSED`). Use it to inspect/modify Blueprints and levels.
- `Binaries/`, `Intermediate/`, `DerivedDataCache/`, `Saved/` are generated; do not edit.
- Git history shows commits are made from the editor workflow (assets + level changes); `.uproject` and `.mcp.json` edits are tooling setup for the MCP plugins.

### Workflow notes (learned the hard way)

- **Git LFS is required.** `.uasset`, `.umap`, `.fbx`, `.png`, `.wav` and `.mp3` go through LFS (`.gitattributes`). `ISIK.uproject` is deliberately plain text, not LFS, so a clone without LFS can still be opened.
- **Do not switch branches or check out files while the editor is open.** It holds assets in memory and the on-disk files change underneath it. Do git work that needs another branch in a `git worktree` at a **short path** (e.g. `C:\wt`): paths under `Content/Fab/Megascans/...` exceed Windows' length limit in deep directories. Use `GIT_LFS_SKIP_SMUDGE=1` when creating one.
- **Binary assets cannot be merged.** Keep one change set per branch, commit a map/Blueprint edit as a single commit, and let the user merge PRs. For stacked PRs use merge commits (not squash) and retarget the child to `main` after the parent merges.
- **Unreal MCP object paths** are `/Game/Folder/Name.Name` (package + object); `/Game/Folder/Name` alone is rejected for `blueprint` parameters. For asset tools (`find_assets`, `get_referencers`, `delete`) the short form works.
- **MCP limits:** `read_graph_dsl` fails on `BP_Telekinezi:EventGraph` ("Cycle detected ... TACEANDBREAK"), so its graph cannot be read or rewritten that way; `compile_blueprint` on `BP_Enemy` raises `REINST_BP_Enemy_C_0` errors with the editor open and does not confirm success. Verify compiles in the editor. A PIE session (even a stale one) makes `compile_blueprint` and `write_graph_dsl` on `BP_Telekinezi` raise the same `REINST_BP_Telekinezi_C_0` errors while the write itself succeeds — re-read the graph with `read_graph_dsl` to confirm rather than trusting the error. A function graph added with `add_function_graph` *can* be read and rewritten with the DSL even when the owning Blueprint's `EventGraph` cannot, so put new logic in its own function and wire only the entry node into `EventGraph` with `create_node`/`connect_pins`.
- **MCP call shape:** `call_tool` takes `toolset_name` plus a bare `tool_name` (not the dotted full name). `ObjectTools.get_properties` wants `instance` + `properties`; `set_properties` wants `instance` + `values` **as a JSON string**. Property names are camelCase and must come from `list_properties`. `IMC_Default`'s `Mappings` array reads back empty through `get_properties`, so Enhanced Input mapping contexts cannot be edited from MCP — bind a new key with an `Input|KeyboardEvents|<Key>` node instead (set `bExecuteWhenPaused` on it via `set_properties` if it must fire while the game is paused).
- **UMG from MCP:** bound widget events (`OnClicked`, `OnHovered`, `OnUnhovered`) must be created with `UMGToolSet.BindToEventProperty` **before** `write_graph_dsl` can reference them as `(event OnClicked(Btn) ...)`; otherwise it fails with "AddEvent|OnClicked(Btn) does not exist". Widget-tree variables only show up as `Variables|<WBP>|Get<Name>` node types after `CompileWidgetBlueprint`, so compile between `ToggleWidgetAsVariable` and the DSL write. `get_node_type_pins` is the reliable way to learn a node's pin order and leaves no stray nodes behind.
- **`mcp__unreal-mcp__call_tool` performs deletes and edits** and is intentionally not allow-listed; expect a permission prompt. Only the discovery tools (`list_toolsets`, `describe_toolset`) and read-only git/gh commands are pre-allowed in `.claude/settings.json` (which is git-ignored).
- **Always check referencers before deleting an asset** (`AssetTools.get_referencers`). Deleting an asset the editor still references silently nulls the reference: removing `Developers/USER/Level/AM_Attack` left `BP_Enemy.LoopAttacking` with an empty montage until it was relinked to the attack montage (now `/Game/Kutun/Characters/Player/Animations/AM_Attack`).
- **Moving assets through MCP** (`AssetTools.move`): loaded referencers are fixed and saved, but maps that are not loaded keep pointing at a redirector. There is no "Fix Up Redirectors" tool. Load each referencing map, make it dirty (set WorldSettings `KillZ` +1 and back), `save_assets([map])`, then confirm with `get_referencers` that the redirector has no referencers. `save_assets` skips packages that are not dirty, and `save_assets([])` saves nothing. `AssetTools.delete` on a redirector can return true but leave the file on disk; after that the editor no longer sees it.
- **Maps and the GameMode cannot be moved from MCP.** Assets referenced by a class default object, such as the project map settings, trigger a "config INI may need Find/Replace, continue?" dialog that auto-answers Cancel under scripting. Point the settings at the new path first (ConfigSettingsToolset, Project/Project/Maps), then move the map by drag-and-drop in the Content Browser.
- **Source files under `Content/` are watched.** Deleting an `.fbx`/`.png`/`.fbm` that an asset was imported from makes auto-reimport offer to delete that asset. Accepting the dialog deleted moved props on 2026-10-11 (restored from git). Restoring sources from git rewrites their timestamps, and the next editor start reimports the assets. Do not delete source files in Explorer.
- **`write_graph_dsl` does not clear the graph.** Rewriting a function or event keeps the previous version's nodes as a disconnected island (they are wired to each other, so they don't look orphaned); `BP_Axe` had collected 323 dead nodes. After rewriting, delete nodes not reachable from the function entry/events (follow exec outputs, then the inputs of every reachable node). Also: a newly added function parameter is not visible to call nodes until the Blueprint is compiled, and `Parent:` call nodes cannot be created from the DSL (don't override an event whose parent call matters).
- **Collapsed (composite) graphs are read-only through MCP.** `create_node`, `find_node_types` and `read_graph_dsl` all fail on a `K2Node_Composite` subgraph with "Cannot cast type 'K2Node_Composite' to 'Blueprint'" — so no new nodes can be added inside one. What *does* work there: `find_nodes`, `get_node_infos`, `get_connected_subgraph`, `connect_pins`, `break_pins`, `set_pin_value` and `delete_node` (they take node/pin refs, not a graph ref). To change behaviour that lives in a collapsed graph, either rewire its existing pins or change the value of a variable it already reads; to add logic, put it in a new function graph and call that from the outer `EventGraph`. `get_connected_subgraph` on one node of the island is the cheapest way to dump a whole collapsed chain.
- **Reading an existing action's live state** without touching `IMC_Default`: the pure node `Input|EnhancedActionValues|<IA_Name>` returns the action's current value every frame (Boolean for a digital action). Use it on Tick for hold-to-repeat behaviour instead of trying to add `Triggered`/`Completed` taps to an input event node you cannot reach.
- **`find_node_types` does not list a Blueprint function of another Blueprint class** (e.g. `Class|WBPHudGrab|SetAxes` came back empty), but `write_graph_dsl` resolves it anyway — write the `Class|<Class>|<Fn>` call and confirm with `read_graph_dsl`. Pass a function's own parameters as keyword args (`:AxisX ...`); the first positional arg binds to the `self` pin.
- **`find_assets` can miss folders** (it did not list `MyBlueprints/Actors`); confirm "empty" with `exists` or a disk listing before deleting a folder.

## Architecture (Content layout)

All game content lives under **`Content/Kutun/`** (reorganized 2026-10-11). Names use a type prefix + PascalCase (`BP_`, `WBP_`, `ABP_`, `BPI_`, `E_`, `SG_`, `SM_`, `SK_`, `SKEL_`, `PHYS_`, `M_`, `MI_`, `T_<Asset>_<Role>`, `NS_`, `SW_`, `ATT_`, `LS_`, `L_`). Animation names from retargets (`MF_Unarmed_*`, `MM_*`) are kept as-is. Folder colors are shared via `Config/DefaultEditorPerProjectUserSettings.ini` `[PathColor]`.

- **`Kutun/Core`**: Blueprint interfaces (`BPI_Stats`, `BPI_CombatTarget`, `BPI_SwordHolder`, `BPI_Surfing`, `BPI_GameInteractions`, `BPI_Interactable`), enums (`E_Stats`, `E_WeaponState`), the live health component `Components/UC_HealthComponent` (an independent `ActorComponent` used by `BP_Telekinezi`, `BP_Enemy` and the tutorial level), `Save/SG_Settings`, and `GameMode/BP_TelekineziGameMode` (`GlobalDefaultGameMode`).

- **Tutorial prompts** use placed instances of `Kutun/Gameplay/BP_TutorialTrigger` (a box trigger with instance-editable `PromptText`, `Duration` — 0 means until the player leaves — and `bTriggerOnce`). On overlap with the player it creates `Kutun/UI/Widgets/WBP_TutorialPrompt`, calls its `SetPromptText`, and shows it; the text wraps at 800px. Add a step by placing another instance and editing its text — do not add per-step events to the Level Blueprint, and do not place a trigger over `PlayerStart` (the player would spawn inside it and may miss the begin-overlap).
- **Pause menu**: `Kutun/UI/Widgets/WBP_PauseMenu` (dim overlay + `DURAKLATILDI` title + `DEVAM ET` / `ANA MENÜ` / `ÇIKIŞ`), styled to match `WBP_MainMenu` (Font_GelioFasolada, gold `0.823,0.701,0.479` idling to red `0.445,0.042,0.016` on hover, 1.15x render scale, `SW_Sword_SwingAndFly` hover sound). Its `EventConstruct` pauses the game, shows the cursor and switches to Game-and-UI input; its `ClosePauseMenu` function undoes all three and removes the widget. `ANA MENÜ` unpauses and `OpenLevel`s `L_Main3DMenu` by short name. `BP_Telekinezi` drives it from an `Escape` key node with **`bExecuteWhenPaused` on** (so it closes while paused) into the `TogglePauseMenu` function, which branches on `IsGamePaused` and keeps the instance in `PauseMenuRef`. Input mode stays Game-and-UI rather than UI-only precisely so that Escape still reaches the pawn. **Escape ends a PIE session**, so test the pause menu in Standalone Game.
- **Death zone**: `Kutun/Gameplay/BP_DeathZone` — a `BoxComponent` root (`DeathBox`, default extent 5000x5000x500, `Trigger` collision profile, hidden in game). `EventActorBeginOverlap` looks for a `UC_HealthComponent` on the overlapping actor (`GetComponentByClass` + cast) and calls `TakeDamage(999999)` on it, so death runs through the normal health path (`UC_HealthComponent.Die`, which shows `WBP_Restart` for the player) and bypasses `BP_Telekinezi.ApplyDamage`'s `bHitImmune` window. Anything with a health component dies, enemies included — deliberate, so they don't fall forever. `Stand_Arena` has one instance, `DeathZone_OutOfBounds`, at (11000, 0, -2500) scaled 20/20/2; it sits **below everything**, because both playable regions of that map have solid ground at z ~= -475/-500 and the real void only starts past the edges of those ground planes.
- **Object scaling / crush** lives on `BP_Telekinezi`, split between a collapsed graph and functions:
  - `EventGraph` -> `S_ScaleUP/Down` (collapsed, so MCP cannot add nodes there) holds `IA_ScaleUp` / `IA_ScaleDown`, wired from **`Started` only** — one discrete step per press, which also gives the camera shake and resets `CrushWobbleTime`. The down path additionally branches on the clamped **Y** axis `<= 0.2` and, if so, runs the crush chain: shutter sound, `CS_Crush` shake at 3.0, `PhysicsHandle.ReleaseComponent`, `ChangeMaterial(false)`, clears `CrushedComp`/`bIsGrabbed`/`bIsTelekinesis`/`bIsGrabbing`, removes `WBP_Ref_Grab`, then destroys the actor (clearing `SwordRef` if it was the sword). **Crushing therefore requires the Y axis to be enabled.**
  - Smooth hold-to-scale is `UpdateObjectScale(DeltaSeconds)`, called from `EventTick` immediately **before** `UpdateCrush` so the target is advanced before the interpolation reads it. It reads the two actions with the pure `Input|EnhancedActionValues|IA_ScaleUp/Down` nodes, stores `ScaleInputDir` (+1/-1/0) and, while grabbing with a valid `CrushedComp`, advances `CrushTargetScale` per axis by `CrushAxisBias * ScaleAxisMask * ScaleSpeed * DeltaSeconds * dir`, clamped to `[ScaleMinAxis, 10]`. `UpdateCrush`'s existing `VInterpTo` (`CrushInterpSpeed` 8) plus the wobble does the smoothing — do not reset `CrushWobbleTime` per frame or the jiggle flatlines.
  - Per-axis masking: keys **1 / 2 / 3** (`Input|KeyboardEvents|1..3` nodes in `EventGraph`) call `ToggleScaleAxis(Axis)` with 0/1/2, which flips `bScaleAxisX/Y/Z` and calls `RefreshScaleAxisMask`. That function derives `ScaleAxisMask` (1/0 per axis) **and** rewrites `CrushAxisBias = BaseAxisBias * mask` — that second part is how the mask also reaches the discrete steps inside the collapsed graph, since they already read `CrushAxisBias`. `BaseAxisBias` holds the real bias `(1, 0.75, 0.9)`; never edit `CrushAxisBias` by hand, edit `BaseAxisBias`. `RefreshScaleAxisMask` also runs on `BeginPlay`. Axis scaling is local to the component (component scale always is), so "only Y" means the object's own length axis.
  - HUD: `WBP_HudGrab` gained `HB_Axes` with `Txt_X`/`Txt_Y`/`Txt_Z` (gold `0.823,0.701,0.479`, Roboto Bold 18, 1px outline) 44px under the grab hand, and a `SetAxes(AxisX, AxisY, AxisZ)` function that sets each text's **render opacity** (1.0 active / 0.25 off) — render opacity rather than colour because `Appearance|SetColorandOpacity` has several ambiguous overloads. `RefreshScaleAxisMask` pushes the state to `WBP_Ref_Grab` when valid, and the widget's own `EventConstruct` pulls it from the player so a freshly created HUD starts correct.
- **Sword-surfing / combat** (recent commits: "new states onswordsurfin"): `Kutun/Weapons/SwordMount`, `Kutun/VFX/{SaberTrail,SwordTrailPack}`, `CombatMagicAnims`, and `Characters/Mannequins`.
